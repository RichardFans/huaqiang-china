# ADR-0009 · 「华强开发度」指标口径

- 状态：Accepted（2026-11-24）
- 背景：「人类对华强的开发不足 0.1%」是B站评论区经典调侃（民间口径，无出处可考）。
  本档案把它严肃化：**给一个公式透明、随数据自动更新、可复算的勘探进度指标**——
  假精确本身就是笑点，但每个数字必须是真的。

## 决策

1. 口径（勘探口径）：
   `华强开发度 = 在册二创条目数 N / 检索探明空间 M`
   - N：`curated.counts.derivative`（管线生成）；
   - M：全部检索清单（search manifests）中 `numResults_total` 的**最大值**——
     即一手快照记录的B站检索命中总数（取最大是保守口径：分母只大不小）。
2. 分母缺数（清单无 numResults）时显示「勘探中」，**不得**编造分母。
3. 呈现：README 生成区一行 + shields.io Endpoint 徽章（JSON 由 build 生成、
   Pages 托管，README 零硬编码数字、零漂移）+ 站点首页。
4. 民间口径「<0.1%」永远以「民间口径」字样出现，不与本指标混同；
   若本指标超过 0.1%，脚注声明：民间估值与勘探口径分母不同，不构成矛盾——
   恰说明华强宇宙深不可测。

## 后果

- 指标随收录增长自动上升，本身就是「档案在生长」的活证；
- `search.py` 双正则解析 numResults（严格 + 混淆变体），manifest 持久化留档；
- 若平台改版导致 numResults 消失，指标自动退化为「勘探中」而非报错。

## 修订（2026-11-24）：分母不可得，平台检索面封顶 1,000 条

解析器修好之后（`numResults` 在混淆 IIFE 的常量表里，按形参下标对位取值，而且映射每次响应
都会重排），对五个关键词实测：numResults 均为 1,000、numPages 均为 50，与关键词无关、
首页候选数各异（66 到 80）。结论：这是平台检索面的硬上限，不是总量。
证据：`data/snapshots/2026-11-24/search/`，自动汇总于 `docs/evidence/search-surface.md`。

因此原口径「在册条目 / 检索探明空间」不成立：拿 1,000 当分母算出的百分比是假精确。

**决策**

1. 分母等于已知封顶值，或同日多个关键词的总数完全一致时，视为封顶，**不出比值**，
   只报告事实：账面条数、封顶值、实测关键词数。封顶值是常量 `config.SEARCH_RESULTS_CAP`。
2. 判定用「等于」而不是「大于等于」：真实总量大于封顶值时并不是封顶。
3. 民间口径「不足 0.1%」保留并明确标注为民间口径。它讲的是这个梗的开发潜力，不是已有视频的
   收录进度，平台检索面既无法证实也无法证伪。
4. 将来平台放开上限，或找到别的总量来源，口径自动回到可复算的比值，无需改代码。

**后果**

- 指标从「一个百分比」变成「一条有证据的观测，加一本照记不误的账」；
- 「想算 0.1% 却撞上天花板」本身成了档案的一条研究发现：发现路线有偏差，检索面只能看到前 1,000 条；
- `zfq.ingest --totals-only` 可以只刷新分母观测，不触发富化入册。
