# ADR-0010 · 榜单实验室（多维排序与筛选）与标签切换

- 状态：Accepted（2026-11-24）
- 背景：用户反馈「各种榜单不能顺序平铺让读者不断下拉，应该用标签切换等更友好的 UI」，
  并希望支持按点赞、投币、评论数等多种指标排序与分类筛选。

## 决策

1. **首页榜单改为标签切换**：殿堂封面 / 热度总榜 / 新晋佳作 / 7 日涨幅四个面板同一区域
   切换（`role=tablist`，支持方向键）。渐进增强：面板全部服务端渲染，无 JS 时
   `<noscript>` 样式展开全部面板——内容不因脚本不可用而丢失。
2. **新增站点 `/charts/` 榜单实验室**：四个维度的组合查询——
   - 时间窗：全部 / 今年 / 近 30 天发布（按 pubdate）；
   - 指标：播放 / 点赞 / 投币 / 收藏 / 弹幕 / 评论（同一最新快照的六个计数字段）；
   - 桥段：五个，多选未做（v1 单选 + 全部）；
   - 形态：八个，下拉单选。
   实现为静态站上的客户端筛选排序：数据以 `<script type="application/json">` 内联随页下发
   （无额外请求、可离线），默认视图（全部 × 播放 × 前 20）服务端渲染，无 JS 仍可读。
3. **口径诚实**：
   - 用户口中的「周榜/月榜」若指**涨幅**口径，需要跨日快照积累；当前快窗只有数日，
     页面明确说明，并指向已有的周涨幅 RSS（track 管线积累后自动有数据）。
   - 所有计数是快照时点值；待复核徽标照挂（ADR-0006）。
4. UI 语言：时间窗与指标用同一 chip 组件（aria-pressed 单选组）；不引入任何前端框架。

## 后果

- 排序筛选逻辑在浏览器端，约 60 行原生 JS；数据体积随在册数线性增长（当前约 200 部、
  每部一条紧凑记录， tens-of-KB 级）；
- 新指标（如「硬币率」等派生量）只需扩展 `_slim` 的 latest 字段与页面数组；
- 若未来在册规模到千级，再考虑分页或虚拟滚动（v1 上限显示前 50）。
